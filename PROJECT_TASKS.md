# Cloud Application

## Этап развития

Фильтрация и контроль состояния облачных сервисов.

## Требования

| ID | Требование |
| --- | --- |
| REQ-01 | API поддерживает получение списка сервисов по состоянию. |
| REQ-02 | Поле `status` принимает только значения `running`, `maintenance` и `stopped`. |
| REQ-03 | Без параметра фильтра API возвращает полный список сервисов. |
| REQ-04 | OpenAPI-документация описывает параметр `status` и допустимые значения. |
| REQ-05 | API возвращает понятную ошибку валидации при неизвестном состоянии сервиса. |

## Acceptance Criteria

### TASK-01

- Некорректное значение `status` отклоняется с HTTP 422.
- В OpenAPI перечислены только три допустимых значения.
- Создание и обновление сервиса также используют общий список допустимых состояний.

### TASK-03

- Параметр `status` является необязательным.
- Запрос без параметра возвращает все сервисы.
- Для каждого допустимого значения возвращаются только соответствующие сервисы.
- URL `/services` без параметров сохраняется.

### TASK-05

- Параметр `status` виден в OpenAPI-документации.
- Документация содержит описание фильтра и допустимые значения.
- Приложение запускается без ошибок.

### TASK-09

- Сортировка не меняет исходные данные.
- API документирует поле и направление сортировки.
- Старые запросы без сортировки продолжают работать.

## Definition of Done

- Изменения реализованы в соответствующих слоях приложения.
- Приложение импортируется и запускается без ошибок.
- Существующий CRUD не нарушен.
- Новая функциональность проверена для положительных и ошибочных сценариев.
- API-документация отражает новый параметр.
- Задача имеет проверяемые критерии приемки.

## Реализованное продолжение проекта

После завершения исходного backlog проект дополнен конфигурацией через `.env`,
PostgreSQL и SQLAlchemy, миграциями Alembic, ограничениями целостности,
объектным хранилищем и учебной аутентификацией. Автоматические проверки
охватывают Pydantic-валидацию, OpenAPI и полный интеграционный цикл REST API.

## Жизненный цикл задачи

`TODO` -> `IN PROGRESS` -> `REVIEW` -> `DONE`

- `TODO` - задача сформулирована и ожидает начала работы.
- `IN PROGRESS` - задача выполняется.
- `REVIEW` - результат проверяется.
- `DONE` - критерии приемки выполнены.
