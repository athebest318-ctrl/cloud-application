# Повторное выполнение ЛР9 и ЛР10

Упражнения выполнены заново в отдельном локальном репозитории CloudApplication_LR09_10. Актуальные main и feature/network-error-handling не откатывались.

Исходные файлы взяты из раннего снимка dc7c64f. До git init подготовлено начальное состояние упражнения: status: str, README и .gitignore отсутствуют, TASK-01 имеет состояние TODO. requirements.txt перекодирован из UTF-16 в UTF-8. Это повторный учебный цикл, а не восстановленная запись первоначальной сдачи.

В ЛР9 созданы четыре коммита. В ЛР10 выполнены полные циклы feature/status-validation и docs/status-description со слиянием в локальную main и удалением обеих локальных веток. Для наглядности использовано merge --no-ff. Удалённые ветки основного проекта не удалялись.

Фактические команды и ответы находятся в evidence/labs_09_10. У записи команды сохранены выходной код и вывод; код 1 у merge-base --is-ancestor до слияния является ожидаемым результатом проверки изоляции.

История учебного репозитория публикуется в удалённую ветку practice/labs-09-10. Локальная main учебной копии не является удалённой main основного проекта.

Репозиторий можно получить отдельно:

```powershell
git clone --single-branch --branch practice/labs-09-10 https://github.com/athebest318-ctrl/cloud-application.git CloudApplication_LR09_10
git branch -m main
git log --oneline --graph --all
```

Для офлайн-восстановления используется CloudApplication_LR09_10.bundle из архива материалов:

```powershell
git clone CloudApplication_LR09_10.bundle CloudApplication_LR09_10
```

ЛР12 выполнена по уточнённому файлу «ЛР 12 (2).docx» — «Конфигурирование облачного приложения». Она продолжает учебную копию после ЛР10. Локальная ветвь feature/app-configuration публикуется под новым удалённым именем practice/lab-12-configuration, существующая одноимённая ветвь пользователя не заменяется. Фактические проверки сохранены в lr12_results.json и lr12_commands.txt; офлайн-история — в CloudApplication_LR12.bundle.
