## Подготовка и ход работы

Использован изолированный Ubuntu 24.04-контейнер с systemd как PID 1. Стенд запускается в Docker Desktop с private cgroup namespace и временными /run, /run/lock и /tmp; каталоги хоста не подключаются. Повышенные полномочия контейнера нужны только для учебного менеджера служб. Службы Windows и Docker Desktop не изменялись. Исходный список failed units пуст.

Схема: unit / reload → start / stop → MainPID → journalctl

## docker / lr35 / service_worker.py

```text
import sys
import time
from datetime import datetime, timezone
from pathlib import Path

FAIL_FLAG = Path('/opt/cloud-lab/fail.flag')
if FAIL_FLAG.exists():
    print('STARTUP ERROR: fail.flag detected', file=sys.stderr, flush=True)
    raise SystemExit(42)
print('cloud-lab-worker started', flush=True)
while True:
    print('heartbeat', datetime.now(timezone.utc).isoformat(), flush=True)
    time.sleep(5)

```

## docker / lr35 / cloud-lab-worker.service

```text

[Service]

ExecStart=/usr/bin/python3 /opt/cloud-lab/service_worker.py
Restart=no
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

## Ответы на контрольные вопросы

1. **Что называется службой серверной ОС?** Фоновый программный компонент, жизненным циклом которого управляет ОС.

2. **Чем служба отличается от обычного процесса?** Процесс является выполняющимся экземпляром; служба дополнительно имеет описание и правила управления.

3. **Что представляет собой systemd?** Менеджер инициализации и служб Linux.

4. **Что называется unit?** Объект конфигурации и управления systemd.

5. **Для чего используется .service unit?** Описывает запуск и параметры фоновой службы.

6. **Для чего используется systemctl?** Управляет и исследует units.

7. **Что делает systemctl status?** Выводит человекочитаемый обзор состояния и последние события.

8. **Что делает systemctl start?** Запускает службу сейчас.

9. **Что делает systemctl stop?** Останавливает работающую службу.

10. **Что делает systemctl restart?** Останавливает и запускает службу снова.

11. **Для чего используется systemctl is-active?** Возвращает краткий результат проверки активности.

12. **Что означает состояние active (running)?** Служба активна и её основной процесс выполняется.

13. **Что означает inactive?** Служба сейчас не работает.

14. **Что означает failed?** Служба завершилась с ошибкой либо нарушила условия запуска.

15. **Для чего используется systemctl is-failed?** Для краткой проверки состояния failed.

16. **Что такое MainPID?** Идентификатор основного процесса службы.

17. **Чем unit отличается от MainPID?** Unit — описание и объект управления, MainPID — номер конкретного процесса.

18. **Для чего используется systemctl show?** Для получения отдельных свойств unit в машинно читаемой форме.

19. **Зачем после изменения unit-файла выполняется daemon-reload?** Чтобы менеджер перечитал изменённую конфигурацию.

20. **Запускает ли daemon-reload службу?** Нет.

21. **Чем enable отличается от start?** Enable настраивает участие в автозапуске; start запускает сейчас.

22. **Чем disable отличается от stop?** Disable убирает автозапуск; stop завершает текущий процесс.

23. **Может ли служба быть active и disabled одновременно?** Да, это показал эксперимент disable без stop.

24. **Может ли служба быть inactive и enabled одновременно?** Да, это показал эксперимент enable без start.

25. **Для чего используется [Install]?** Описывает подключение unit к целям при установке.

26. **Какое назначение имеет WantedBy=multi-user.target?** Подключает службу к target многопользовательского режима через enable.

27. **Для чего используется journalctl?** Просматривает системный журнал.

28. **Как получить журнал только одной службы?** journalctl -u cloud-lab-worker.service.

29. **Для чего используется journalctl -f?** Для наблюдения новых записей в реальном времени.

30. **Останавливает ли Ctrl+C службу при просмотре journalctl -f?** Нет, прекращается только просмотр журнала.

31. **Для чего используется ключ -b?** Для выбора событий текущей загрузки.

32. **Как ограничить журнал последними 20 событиями?** journalctl -u cloud-lab-worker.service -n 20.

33. **Как выбрать события за последние пять минут?** journalctl -u cloud-lab-worker.service --since "5 minutes ago".

34. **Какая последовательность используется для первичной диагностики отказа?** status, show, journalctl; затем проверка причины, исправление, reset-failed и start.

35. **Что показывает ExecMainStatus?** Код завершения основного процесса.

36. **Почему в учебном отказе используется код 42?** Для однозначного распознавания специально введённого отказа.

37. **Для чего используется reset-failed?** Сбрасывает сохранённое состояние отказа и связанные ограничения запуска.

38. **Устраняет ли reset-failed первопричину ошибки?** Нет.

39. **Почему сначала необходимо устранить причину, а затем запускать службу?** Иначе ошибка воспроизведётся при следующем запуске.

40. **Для чего используется Restart=on-failure?** Для автоматического повторного запуска после неуспешного завершения.

41. **Почему автоматический restart не заменяет диагностику?** Он может снова запускать неисправную программу и создавать цикл отказов.

42. **Почему на удалённом сервере нельзя без необходимости останавливать SSH?** Можно потерять единственный канал управления сервером.

43. **Как знания о systemd будут применяться при развертывании реального серверного приложения?** Будут применяться unit-файл, сервисный пользователь, управление запуском и журналы уже реального приложения.
