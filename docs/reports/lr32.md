## Цель работы

Воспроизвести off-by-one в retry, установить первопричину и проверить исправленный алгоритм.

## Подготовка и ход работы

Рабочий main уже содержит правильный цикл. Учебный дефект range(1,max_attempts) внесён в отдельную временную копию. Сценарий использует 127.0.0.1:9999, timeout=0.5, max_attempts=3 и retry_delay=0.1; к PostgreSQL не обращается. В pdb перед циклом проверены max_attempts=3 и URL; вычислены [1,2] и [1,2,3]. На условной остановке attempt == 3 оба значения attempt и max_attempts равны 3.

Схема: Две попытки → Гипотеза range → Остановка / стек → Исправление

## scripts / debug_notification_client.py

```text
"""Reproduce retry exhaustion against a local, unavailable endpoint."""

import argparse
import asyncio
import os
import socket
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("--attempts", type=int, default=3)
    args = parser.parse_args()
    if args.attempts < 1:
        parser.error("--attempts must be positive")
    with socket.socket() as probe:
        probe.settimeout(0.2)
        if probe.connect_ex(("127.0.0.1", 9999)) == 0:
            raise RuntimeError("Port 9999 is in use; choose a free test endpoint")
    os.environ.update(
        {
            "NOTIFICATION_SERVICE_URL": "http://127.0.0.1:9999",
            "NOTIFICATION_TIMEOUT_SECONDS": "0.5",
            "NOTIFICATION_MAX_ATTEMPTS": str(args.attempts),
            "NOTIFICATION_RETRY_DELAY_SECONDS": "0.1",
            "LOG_LEVEL": "DEBUG",
        }
    )
    from app.config import settings
    from app.integrations.notification_client import (
        NotificationServiceUnavailable,
        send_notification,
    )
    from app.logging_config import configure_logging

    configure_logging(settings.log_level)
    print(f"Configured max attempts: {settings.notification_max_attempts}")
    try:
        asyncio.run(send_notification("debug@cloud.local", "LR32 debug"))
    except NotificationServiceUnavailable:
        print("EXPECTED_RESULT: service unavailable")
    else:
        raise RuntimeError("Unexpected success")


if __name__ == "__main__":
    main()

```

## Ответы на контрольные вопросы

1. **Что называется отладкой программного кода?** Поиск, локализация и устранение дефекта с проверкой результата.

2. **Чем симптом ошибки отличается от её первопричины?** Симптом наблюдается снаружи, первопричина объясняет механизм ошибки.

3. **Почему ошибка должна быть воспроизводимой?** Чтобы сравнение до и после исправления было достоверным.

4. **Для чего перед debugger используются журналы ЛР №31?** Они показывают фактические номера попыток и помогают выбрать участок исследования.

5. **Что такое breakpoint?** Точка остановки выполнения программы.

6. **Как запустить отладку в VS Code?** Выбрать конфигурацию Python Debugger и нажать F5.

7. **Для чего используется F5?** Запускает отладку или продолжает выполнение до следующей остановки.

8. **Что делает Step Over?** Выполняет текущую строку, не заходя внутрь вызываемой функции.

9. **Что делает Step Into?** Переходит внутрь вызываемой функции.

10. **Что делает Step Out?** Продолжает выполнение до возврата из текущей функции.

11. **Для чего используется панель Variables?** Для просмотра текущих локальных и глобальных переменных.

12. **Для чего используется Watch?** Для наблюдения выбранных выражений.

13. **Что показывает Call Stack?** Цепочку активных вызовов, которая привела к текущей строке.

14. **Что представляет собой Debug Console?** Консоль вычисления выражений в контексте остановленного процесса.

15. **Что называется логической ошибкой?** Программа запускается, но выполняет неверную последовательность действий.

16. **Что называется off-by-one error?** Ошибка на единицу в границе диапазона или количестве действий.

17. **Включает ли range(start, stop) значение stop?** Нет, stop исключён.

18. **Какие значения создаёт range(1, 3)?** 1 и 2.

19. **Почему при max_attempts = 3 ошибочный цикл выполняет только две итерации?** range(1, 3) не содержит 3.

20. **Какое исправление было внесено?** В учебной копии верхняя граница изменена на max_attempts + 1; рабочий исходный цикл уже содержал правильный вариант.

21. **Почему используется max_attempts + 1?** Чтобы включить max_attempts в последовательность.

22. **Как debugger подтвердил корректность значения конфигурации?** В точке остановки max_attempts равнялся 3, URL содержал порт 9999.

23. **Какие выражения исследовались в Watch?** max_attempts; list(range(1,max_attempts)); list(range(1,max_attempts+1)); attempt == max_attempts.

24. **Почему ветвь attempt == max_attempts была недостижима до исправления?** Номер попытки ни разу не достигал исключённой верхней границы.

25. **Зачем выполняется повтор исходного сценария после исправления?** Чтобы подтвердить устранение исходного симптома.

26. **Что называется регрессией?** Нарушение ранее работавшего поведения после изменения.

27. **Почему после исправления проверяется успешный межсервисный запрос?** Чтобы исправление отказа не сломало штатную доставку уведомлений.

28. **Для чего используется conditional breakpoint?** Для остановки только при интересующем состоянии, например attempt == 3.

29. **Что позволяет выполнять Debug Console?** Вычислять выражения, просматривать значения и при необходимости менять состояние; в работе значения только читались.

30. **Для чего предназначена встроенная функция breakpoint()?** Запускает интерактивный Python debugger в текущей строке.

31. **Почему breakpoint() необходимо удалить после эксперимента?** Чтобы рабочее приложение не останавливалось в ожидании ввода.

32. **Чем debugger отличается от print()?** Позволяет останавливать выполнение, исследовать стек и вычислять выражения без множества временных print.

33. **Почему при отладке желательно изменять минимальный участок кода?** Так проще связать изменение с наблюдаемым результатом.

35. **Зачем проблема изолируется в небольшом воспроизводимом сценарии?** Это уменьшает число внешних причин и делает эксперимент повторяемым.

36. **Как журналы и debugger дополняют друг друга?** Журналы показывают историю, debugger показывает состояние на конкретной строке.

37. **Почему глубокая отладка внутреннего кода HTTPX не требуется в этой работе?** Исследуется граница собственного цикла, а не реализация HTTPX.

38. **Что произойдёт в ошибочном варианте при max_attempts = 1?** range(1,1) пуст: запрос не будет выполнен; исправленный вариант делает одну попытку.
